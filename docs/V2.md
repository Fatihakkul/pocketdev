# V2 — Proje tipinden bağımsız, açık kaynağa hazır köprü

## Amaç

**Asıl hedef (baştan beri değişmedi): telefondan geliştirme yapabilmek.**
Yapay zekâ Mac'te kod yazarken, çıktısını telefonda **canlı** görmek ve
geliştirme sürecinin tamamını telefondan yönetebilmek. Telegram bu döngünün
kumanda yüzeyi; `/preview` ve `/otabuild` ile kurulan dağıtım altyapısı ise
aynı döngünün **test ve canlı önizleme** ayağını çözüyor — ayrı bir ürün değil,
bu hedefin parçası.

Bu ayrım konumlandırma açısından önemli (bkz. Adım 4): proje ne "bir Telegram
botu" ne de "bir EAS alternatifi"; **telefon merkezli bir geliştirme döngüsü.**
Dağıtım katmanı o döngünün en zor parçası olduğu için en görünür kısmı, ama
manşeti değil.

İkinci hedef: bunu hiçbir ücret ödemeden yapmak, yani bireysel geliştiricinin
ödediği servis ücretlerini sıfırlamak. Bugün bu proje
bir kişi (ve bir Expo projesi) için çalışıyor; V2'nin hedefi aynı döngüyü
**herhangi bir React Native projesinde** ve **başkasının makinesinde** kurulabilir
hale getirmek, sonra açık kaynak yayınlamak.

Bugün ücretsizleştirilmiş olanlar:

| İş | Ücretli karşılığı | Bu projedeki hali |
|---|---|---|
| iOS build | EAS Build kredisi | yerel `xcodebuild` (`/localbuild`, `/otabuild`) |
| Test cihazına dağıtım | TestFlight / EAS Submit | yerel `.ipa` + Tailscale Funnel (`/otabuild`) |
| Tünel/hosting | ngrok Pro, VPS | Tailscale Funnel (ücretsiz), cloudflared (yedek) |
| Uzaktan geliştirme | — | Telegram + web paneli üzerinden Claude Code |

V2 bu listeye bir şey eklemiyor; **var olanı taşınabilir kılıyor.**

## Hedef mimari: ProjectAdapter

Tek bir arayüz, proje tipine göre iki (ileride daha fazla) uygulama. Runner'lar
adapter'ı çağırır; Katman 2 hiç değişmez.

```ts
export type ProjectKind = "expo" | "react-native-cli";

export interface AppInfo {
  bundleId: string;
  appName: string;
  version: string;
  iconPath: string;
}

export interface DevServer {
  /** Cihazın bağlanacağı adres. Expo'da deep link, RN CLI'da host:port. */
  connectHint: string;
  serverUrl: string;
  stop(): Promise<void>;
}

export interface ProjectAdapter {
  readonly kind: ProjectKind;

  /** Uygulama kimliği ve sürümü — imzalama profili bununla seçiliyor. */
  readAppInfo(projectPath: string): Promise<AppInfo>;

  /** Native projeyi JS bağımlılıklarıyla eşitler; gerekmiyorsa false döner. */
  syncNative(projectPath: string, onProgress?: ProgressFn): Promise<boolean>;

  /** Metro'yu başlatır; tünel gerekiyorsa tunnel.ts üzerinden. */
  startDevServer(projectPath: string, opts: DevServerOptions): Promise<DevServer>;

  /** Bağlı cihaza Debug build kurar (/localbuild). */
  runOnDevice(projectPath: string, udid: string, onProgress?: ProgressFn): Promise<void>;

  /** Bu adapter'da desteklenmeyen komutlar (ör. RN CLI'da /qabuild). */
  supports(command: string): boolean;
}
```

**Tespit:** `package.json`'da `expo` bağımlılığı ya da `app.json`'da `expo`
anahtarı varsa `expo`; yoksa `ios/Podfile` + `react-native` bağımlılığı varsa
`react-native-cli`; ikisi de yoksa iOS komutları kapalı (Claude sürme katmanı
yine çalışır).

**Tespit sonucu önbelleğe alınmamalı** — kullanıcı proje içinde bağımlılık
ekleyip çıkarabiliyor; `syncNative`'in damga dosyası zaten bunu izliyor.

### Aday A — Başarısızlıkta log değil teşhis (öncelikli)

Build patladığında kullanıcıya log kuyruğu göstermek yerine, **Claude'a log
dosyasını okutup tek cümlelik teşhis ve önerilen düzeltmeyi** göstermek.

basıyor. Bu, sürtünmenin en yüksek olduğu an ve en az yardımın verildiği yer.

işaretlendiği için tailnet-içi `serve` tek başına yetmiyor; ya o karar gözden
geçirilir ya panele bir token eklenir.

`/record` (RN CLI'da hâlâ denenmemiş, kullanıcı kararıyla ertelendi) "kullanıcı
yalnızca çıktıyı görmek ister" tezinin en doğrudan karşılığı: kurulum
gerektirmeden, uygulamanın çalışan hâlini telefona göndermek. Öncelik kararı
kullanıcının, ama bu tartışma onu yukarı taşıyor.

## Kapsam dışı (şimdilik)

- **Android.** Tüm build/dağıtım katmanı iOS'a özgü. Android'de imzalama ve
  dağıtım tamamen farklı ve daha kolay — sonraya.
- **Cihaza Tailscale kurmak.** Kullanıcı istemedi; `/preview` için tünel çözümü
  bunu şart koşmamalı.
- **Çok kullanıcılı çalışma.** Bugün tek kullanıcı (`ALLOWED_USER_ID`) ve tek
  makine varsayımı var; açık kaynak sürüm de "kendi makinende kendin için
  çalıştır" modelinde kalacak.

## Doğrulanmamış noktalar

Plana girdi olan ama henüz ölçülmemiş şeyler — uygulama sırasında ilk iş bunları
sınamak:

0. **ÇÖZÜLDÜ (2026-08-12) — tünel sağlık kontrolü yanlış yolu soruyordu.**
   `/preview` ilk denemede 4 dakika bekleyip "Adres açıldı ama erişilebilir
   olmadı" dedi. Tünel baştan beri çalışıyordu: `waitUntilReachable` 2xx bekliyor
   ve `/` isteğine Metro **404** dönüyor (`HEAD /status` → 200). `/otabuild`'de
   sorun çıkmamıştı çünkü OTA sunucusu `/`'da kurulum sayfasını 200 ile veriyor.
   `openTunnel` artık `healthPath` alıyor; Metro için `/status`. Hata mesajına
   son HTTP durumu da eklendi — "bağlantı kurulamadı" ile "erişildi ama 404"
   tamamen farklı iki sorun ve eskisi ikisini ayırt etmiyordu.

   tailscaled logu bunu kesinleştirdi: `02:06:50 listening on 100.75.217.76:443`
   ile `02:10:50 closing listener` arasında tek bir TLS hatası bile yok, yani
   bağlantı kuruluyordu.

1. **CEVAPLANDI (2026-08-12): RN CLI dev client'ı kutudan çıktığı haliyle https
   tünele bağlanamaz — uygulama tarafında tek satır gerekiyor.**

   Kaynaktan kesinleşti (RN 0.83.1):
   - `RCTDevMenu.mm` → "Configure Bundler" **üç** alan soruyor: adres, port,
     entrypoint. **Şema alanı yok**, yazdığı tek şey `jsLocation`.
   - `RCTBundleURLProvider.mm` → `packagerScheme`, NSUserDefaults'taki
     `RCT_packager_scheme` anahtarından okunuyor ve boşsa **`"http"`**.
     `defaults` sözlüğü yalnızca `RCT_enableDev` ve `RCT_enableMinification`
     tohumluyor, şemayı hiç yazmıyor.
   - `serverRootWithHostPort` → `http://host:443/` kuruyor; TLS-only Funnel'a
     düz HTTP gidiyor ve bağlantı kurulmuyor.

   Build zamanı enjeksiyon **mümkün değil**: değer NSUserDefaults'ta, derleme
   sabiti değil. `ip.txt` yolu da kapalı — `guessPackagerHost` yalnızca host
   okuyor ve doğrulamayı `scheme:nil` ile yapıyor. Launch argument
   (`-RCT_packager_scheme https`) NSArgumentDomain'e düşüyor, yani kullanıcı
   uygulamayı ikonundan açtığında kayboluyor.

   Kalıcı tek yol `setPackagerScheme:` (bu `updateValue:forKey:` ile
   NSUserDefaults'a yazıyor), yani `AppDelegate`'in `bundleURL()`'ünde
   `#if DEBUG` altında:

   Ama **`packagerScheme`'i ayarlamak tek başına yetmiyor** — RN 0.83.1'de bir
   hata var (ayrıntı ve bildirim taslağı: `UPSTREAM_BUGS.md`).
   `RCTBundleURLProvider.mm`:

   ```objc
   + (NSURL *)jsBundleURLForBundleRoot:...packagerScheme:(NSString *)scheme ...
   {
     return [self jsBundleURLForBundleRoot:bundleRoot
                              packagerHost:packagerHost
                            packagerScheme:nil          // ← aldığı şemayı çöpe atıyor
                                       ...];
   }
   ```

   Bu 8 argümanlı aşırı yükleme, aldığı şemayı 9 argümanlı sürüme `nil` olarak
   geçiyor; `serverRootWithHostPort` de `nil`'i `"http"` yapıyor. Instance
   metodu `jsBundleURL(forBundleRoot:)` tam bu yolu kullanıyor, dolayısıyla
   ayar URL'e hiç yansımıyor. Cihaz logunda birebir şu görüldü:

   ```
   [bridge] jsLocation=<host>.ts.net:443  scheme=https  url=http://<host>.ts.net:443/index.bundle?...
   ```

   Çözüm 9 argümanlı sürümü doğrudan çağırmak:

   ```swift
   let settings = RCTBundleURLProvider.sharedSettings()
   let location = settings.jsLocation ?? ""
   let useHTTPS = location.contains(".ts.net")
   settings.packagerScheme = useHTTPS ? "https" : "http"   // isPackagerRunning + RCTPackagerConnection bunu okuyor
   guard useHTTPS else { return settings.jsBundleURL(forBundleRoot: "index") }
   return RCTBundleURLProvider.jsBundleURL(
     forBundleRoot: "index", packagerHost: location, packagerScheme: "https",
     enableDev: settings.enableDev, enableMinification: settings.enableMinification,
     inlineSourceMap: settings.inlineSourceMap, modulesOnly: false,
     runModule: true, additionalOptions: nil)
   ```

   `packagerScheme` ataması yine de şart: yalnızca bundle URL'i için değil,
   Metro'nun ayakta olduğunu doğrulayan `isPackagerRunning` ve fast refresh'in
   websocket'ini kuran `RCTPackagerConnection` da onu okuyor.

   Sabit `"https"` yazmak yanlış olurdu: aynı Wi-Fi'daki yerel geliştirme
   build'e gömülen LAN IP'sine (`ip.txt`) düz http ile bağlanıyor. Karar her
   açılışta yeniden veriliyor ki ayar NSUserDefaults'ta https'e takılı kalmasın.
   Release hiç etkilenmiyor — o dal gömülü bundle'ı kullanıyor ve
   `RCTBundleURLProvider`'a hiç uğramıyor.

   **Yan bulgu — tünel tarafı doğrulandı:** `packagerServerHostPort`, adresi
   kullanmadan önce `isPackagerRunning:location scheme:@"https"` ile Metro'yu
   sınıyor ve bu kontrol GEÇTİ (geçmeseydi `location` nil olur, uygulama gömülü
   bundle'a düşerdi). Yani **Tailscale Funnel üzerinden https ile Metro'ya
   erişim çalışıyor**; kırık olan tek şey URL kurulumuydu.

   **Doğrulandı (2026-08-12):** example-rn-app'ye uygulandı, `/localbuild` ile
   cihaza kuruldu ve telefon hücresel veriden Tailscale Funnel üzerinden
   Metro'ya bağlandı — `/preview` sorunsuz çalışıyor.
